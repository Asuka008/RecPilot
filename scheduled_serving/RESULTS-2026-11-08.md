# Bounded serving load experiment

The serial service delivered more successful recommendations at high load in this sweep. Keep it as the performance reference. The bounded scheduler returned explicit overload responses and shortened the time clients spent waiting for many failed attempts. Its largest regression occurred with 32 closed-loop clients.

## Matched measurements

Each row compares one 60-second serial run with one 60-second scheduled run using the same client implementation, model ID, 100-history corpus, connection policy and load setting. These are runs at different times. The corresponding core and scheduled service manifests identify A100 MIG 2g.20gb, FP32 with TF32 disabled. The load reports share one scheduled process instance. Client sample counts, window QPS, error categories and p99 values were recomputed. Server counter and histogram deltas match their snapshots. Written recommendation counts for 200/503/504 reconcile with client outcomes.

Each arrow runs from serial to scheduled. QPS counts successes completed inside the window. Success percentage uses all offered requests, including unsent client drops, and counts completions during drain. The all-attempt p99 includes time until a failed attempt ended and excludes unsent arrivals. Queue and core times are scheduled-server means for jobs that started execution, including work whose results later expired. Core covers the complete recommendation call.

At 200 scheduled arrivals/s, 163 of 12,000 received 503. At 400/s, client drops fell from 12,210 to 72 of 24,000. Of the 23,928 attempted requests, 9,368 succeeded, 14,542 received 503, one received 504 and 17 disconnected. More arrivals reached admission and received a quick outcome. Fewer received recommendations than the serial service's 11,656.

With 32 closed-loop clients, 103 of 51,584 attempts eventually succeeded, including 87 within the window. Clients saw 46,451 responses with 503, 4,977 with 504, 52 disconnects and one incomplete read. The prior serial run had 14,537 attempts at the same concurrency. Closed-loop clients immediately start another request after a refusal, so these runs also differ in arrival pressure. Successful p99 at this point is based on only 103 responses.

For closed-32 jobs that began execution, mean queue residence was 173.67 ms and mean core wall time was 45.52 ms. The configured execution cutoff is 190 ms after accept, leaving 10 ms for the response. The worker discarded 1,215 results after cancellation. Queue capacity bounds waiting job count. CPU scheduling delays and non-preemptible work can still consume the time budget. Per-connection handler/timer creation and immediate client resubmission are plausible contributors. A trace of the loaded service or a controlled implementation comparison would be needed to attribute their costs. The old core profiler measured a different workload.
