# 21｜先定位问题，再选择长尾与冷启动方法

日期：2026-10-23。用户要求先调研工业做法，暂停连续尝试新配方。
本页取代“标题实验结束后直接做 HSTU/ItemCF 融合”的默认安排。
本次完成公开一手资料调研和本地代码审查；没有执行新的训练或测试集评估。

## 1. 需要修正的判断

此前 Mean 对照、标题初始化和固定融合是有效的受控实验，但从这些实验直接跳到
“再融合 ItemCF”缺少机制诊断。我们应先回答：标题有没有可用信号、模型有没有学会
使用它、目标究竟排在什么位置，再选择改动。单元测试 PASS 证明实现满足所测契约，
不能证明实验假设合理。

当前结果支持：**这两个简单标题接入方式没有解决低频命中问题**。
不能扩展为“内容无用”“HSTU 天生不能推荐长尾”或“换一个骨干就能解决”。

区分三个问题：

| 问题 | 本项目定义与证据 | 不能混淆的事 |
|---|---|---|
| 少交互物品 | 训练历史频次 1–5；验证集 7,264 个目标，原始 HSTU R@20=0，ItemCF=.04790749，Mean=.01362885 | 已有行为信号，但当前模型未有效命中；不是所有物品都没有正向监督 |
| 零交互物品 | 730 个目录物品没有训练历史交互；验证目标 844 个 | 已知目录下的零正交互，不等于真实刚发布，也不等于从未进入训练计算 |
| 热门占据排序 | 原始 HSTU 验证 Top-20 推荐槽位的 96.9054% 属于频次 21+ | 推荐槽位分布不是日志中的曝光分布；降热门分数不自动产生个性化冷启动能力 |

已有监督审计显示：验证 1–5 组只有 74/7,264 个目标没有保留的正预测位置。
“低频都没被监督过”不足以解释整个组零命中。诊断与选择继续只用训练/验证数据。
完整历史结果见[笔记 20](learning-20-title-hstu-controls.md)及其引用。

## 2. 工业公开方案实际在处理什么

这里的“常见路线”指多个工业论文或官方产品文档反复出现的机制，不是行业采用率统计。
论文里的上线收益是作者报告，不代表我们独立复核，也不能移植成 MicroLens 的预期涨幅。

### 内容到偏好的共享映射

微软 CB2CF 在有交互的物品上学习从内容到协同表示的映射，再为冷物品产生表示；
其场景是 Microsoft Store 的相似物品推荐。YouTube 的内容推荐工作用共同观看关系
监督视觉表示，而不只比较通用视觉相似度。两者提示：内容编码和推荐偏好之间通常还
需要学习连接。本项目可以借鉴共享映射，但不能把它们当作 HSTU 同协议效果证据。
来源：[CB2CF 作者论文，RecSys 2019](https://www.noamko.org/papers/recsys19-sub1369-CB2CF.pdf)、
[Google Research，2016 演示论文](https://research.google/pubs/content-based-related-video-recommendations/)。

快手 M3CSR 的官方 RecSys 2024 摘要同样明确指出“多模态特征提取”和“用户兴趣建模”
之间存在差距，其方法包含可学习的内容映射、聚类类别表示及用户模态兴趣建模。
摘要报告已上线。此处仅核实了会议官网的作者摘要，ACM 全文未成功访问，
因此不据此声称掌握其训练细节或具体线上提升。
来源：[RecSys 官方摘要](https://recsys.acm.org/recsys24/accepted-contributions/)。

### 在训练时练习缺少交互信息

DropoutNet 在训练中丢弃偏好输入，使模型学习在协同信息缺失时使用内容。
阿里云 PAI 的冷启动文档将其列为可用模型，并提供训练部署入口。
这与 HSTU 已有的普通神经层 dropout 不同；我们没有做物品 ID/偏好信息缺失训练。
原论文的冷启动划分和候选范围也不同，不能直接横比数值。
来源：[DropoutNet，NeurIPS 2017](https://proceedings.neurips.cc/paper_files/paper/2017/file/dbd22ba3bd0df8f385bdac3e9f8be207-Paper.pdf)、
[阿里云冷启动候选生成文档](https://www.alibabacloud.com/help/en/airec/what-is-pai-rec/use-cases/cold-start-recall)。

### 诊断历史特征依赖，再修正训练或排序

Pinterest 的 Warmer for Less 从特征梯度等证据诊断历史信息占主导，提出非历史特征路径、
正则化及数据增强。作者报告生产应用；当前查阅的是 2025 年预印本。
它研究带历史/非历史特征的排序预测，并非我们的全目录序列检索。
值得借鉴的是诊断过程，不能未经验证就照搬其损失或强行拉齐冷热分数。
来源：[Pinterest 作者预印本及正文](https://arxiv.org/html/2512.17277v1)。

另一个容易误用的概念是“频次修正”。Google 的神经召回论文处理批内负样本的抽样偏差；
我们的全目录交叉熵没有同一种负采样分布。现有推理时减去频次项的改进，不能称为
复现了该训练校正，也不能视为曝光倾向校正。
来源：[Google，Sampling-Bias-Corrected Neural Modeling，2019](https://research.google/pubs/sampling-bias-corrected-neural-modeling-for-large-corpus-item-recommendations/)。

### 冷启动候选通道和探索反馈

阿里云文档同时列出规则、内容偏好和专用模型候选生成，随机分配可作为基准。
Google 的 2025 年探索流量工作研究如何分配有限探索预算，并报告线上应用。
它们解决的不只是静态向量质量，还包括新内容获得反馈的机会。
来源：[阿里云文档](https://www.alibabacloud.com/help/en/airec/what-is-pai-rec/use-cases/cold-start-recall)、
[Item Level Exploration Traffic Allocation，2025](https://arxiv.org/abs/2505.09033)。

我们目前已对所有 19,220 个目录物品精确打分，没有 ANN 或上游召回遗漏。
增加 ItemCF 在本项目中意味着改变评分/排序，不能称为补回从未进入候选池的物品。
当前数据也缺少曝光、未点击展示、可靠发布时间和在线反馈，不能验证探索策略的
因果收益；不应以一个离线模拟器冒充线上冷启动闭环。

## 3. 代码审查：之前究竟检验了什么

### 固定标题融合的表达能力

代码路径：[`projection.py`](../content_hstu/projection.py) →
[`ContentLookup`](../content_hstu/model.py) →
[`IDHSTU.score_candidates`](../src/models/id_hstu.py)。

- 冻结标题缓存为 `[19221,384]`，第 0 行是 padding。
- 在训练历史物品上拟合固定 PCA，得到 `[19221,64]` 的固定表 `S`。
- 初始化实验把可训练表 `E` 初始化为 `S`，后续按普通 ID 参数更新。
- 融合实验使用 `V_i = E_i + 0.5*S_i`；历史输入 `[B,L,64]` 与候选输出
  `[19220,64]` 都从同一个有效表取值，归一化后打分。

**由实现可直接推导的限制：**在固定目录内，`E_i` 是每个物品独立、自由的参数。
对任意目标表 `V`，都可以取 `E=V-0.5*S`。所以固定相加没有扩大 ID 查表在该目录
上的可表示函数集合；它改变的是初值、优化轨迹和正则化先验。
这不表示训练必然完全抵消了标题，也不表示两个实验的训练过程等价。

我们没有一个由交互监督学习的共享内容映射，也没有 ID 信息缺失训练。
为了匹配参数量而采用固定 PCA 是明确的对照选择，但它限制了能检验的冷启动机制。
PCA 保留约 57.90% 方差，不等于“保留了 57.90% 推荐语义”。
不能把这次负结果包装为完整的工业内容推荐方案已被否定。

### 零交互不等于完全没被训练影响

[`full_catalog_loss`](../src/microlens_training.py) 对每个有效预测位置计算所有
非 padding 候选的交叉熵，logits 形状为 `[有效预测位置数,19220]`。
对温度缩放后的 logit，梯度为 `p_j - 1[j=target]`。
零正交互物品仍参加分母，并可能收到非目标候选梯度；标题初始化的 ID 向量
也会继续更新。不能将这些表行解释成从未改变的原始标题向量。

这指出需要检查的训练压力，但尚未证明它是长尾失败的主要原因。
模型归一化、共享参数和训练动态都影响结果；不能据此断言每个冷物品分数单调降低。
更不能读取验证/测试标签来删除“负例”，或把未交互直接当成已曝光且不喜欢。

## 4. 下一步：一次验证集机制审计，不增加 30 轮训练

**最先实现的产物是独立诊断报告。以下入口尚未实现，不是已有运行结果。**
复用冻结缓存、现有检查点和配对身份检查，保留原始模型源码与配置。
报告必须记录 Git、数据/缓存/检查点哈希、实际 GPU/软件栈、耗时及峰值显存。

| 检查 | 固定方法 | 用来决定什么 |
|---|---|---|
| 标题是否提供可直接利用的信号 | 用可见训练历史的标题均值查询，对全目录做余弦排序；比较原始 384 维与现有 PCA 64 维；沿用 L=32、完整可见历史过滤和稳定同分规则 | 区分当前标题表示弱，还是投影/后续训练使用方式值得继续检查 |
| 破坏内容关联的对照 | 固定一个预登记种子，在训练频次组内置换物品与标题行的对应；同一个置换用于历史和候选，padding 不动 | 保持频次组及向量分布，检查真实内容关联是否胜过这种破坏；单次置换只是诊断，不构成显著性检验 |
| 目标排到哪里 | 原始 HSTU、title-init、title-fusion 各只做验证推理；报告各频次组目标排名分布、R@20/100/500/1000 与 Top-20 分差 | 区分接近阈值的排序问题与远离用户表示的问题；大 K 诊断不是替换原始主指标 |
| 现有协同信号是否互补 | 同一用户、同一 K=20 比较 HSTU 与 ItemCF 的独有/共同命中；按训练频次分组 | 判断是否值得研究评分组合；两路并集是上限诊断，不能冒充实际 Top-20 成绩 |

标题均值是未经偏好训练的诊断器；弱结果不能证明任何监督学习都无法使用标题。
也不从“句子相似”直接推导“用户喜欢”。不为看起来好的结果临时扩展编码器、权重或 K 搜索。

完成标准：候选/用户身份与既有验证协议一致，原始 HSTU 指标复现；生成上述对照、
排名和命中证据，选择一个具体机制或记录证据不足。该报告不读取测试目标。
模型推理必须在服务器运行；本地只准备代码、合成契约检查和轻量验证。
现在无需重复已经通过的训练、标题编码或测试集评估。

## 5. 审计之后才决定的改动

1. **若内容有信号，且证据指向当前接入方式：**优先考虑小型共享内容映射
   `384→64`，由推荐任务学习；再单独消融 ID/偏好输入丢弃。
   两个机制分开比较，明确历史和候选两端如何工作，以及无 ID 正交互时走哪条路径。
   这属于借鉴内容对齐和缺失信息训练思想，不是宣称复现 DropoutNet/M3CSR。
   参数增加必须报告，并与同规模的非语义对照区分。蒸馏一个偏热门教师也可能继承其偏差。
2. **若目标接近 Top-20，且 ItemCF 独有命中充分：**才考虑一个小范围、预登记的
   分数组合实验；不要假定存在独有命中就一定能在固定 K 内兼得。它主要面向有交互物品。
3. **若证据不足：**停止增加融合配方，把负结果写清楚。进一步学一个训练集监督的
   小内容探针或审查标题质量，需要另立假设；不自动下载视频、不换大模型。

任何正式候选都先登记目标、预算和取舍：总体 NDCG@10、1–5 组 Recall@20、零频组
分别报告；要求胜过配对基线并报告命中数，不能把偶然一条命中说成解决长尾。
若接受总体精度下降来改善覆盖，必须事先明确容忍值，而不是看到结果后改口径。
单种子筛选后，对固定配方和对应基线做多种子验证，再谈稳健提升。

同一个测试集已被多个冻结配方报告过；后续不能再称为完全未接触的独立确认集。
不从这些测试切片选新参数，并如实记录实验次数。严格新物品泛化需要额外的物品留出
或有可用时间的全局时间协议，与当前已知目录 leave-one-out 分开版本化。
