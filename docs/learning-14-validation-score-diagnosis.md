## 下一项小实验：冻结模型，只调整输出分数

保留 epoch 28 的 best.pt、物品映射、用户划分和所有过滤/排名规则。
为每个候选 i 计算：

`adjusted_score(i) = cosine(query, item_i) - T * alpha * log(c_i + s)`

- T 使用原训练 temperature=0.2，不作为新调参项。
- c_i 是训练中**保留的有效正标签事件数**，按 `train[-(L+1):][1:]` 统计。
- s 固定为 1，避免零频物品的 log(0)。
- alpha 预先固定为 0、0.25、0.5、1.0，共 4 档，不边看结果边扩大搜索。

它的排序等价于 `cosine/T - alpha*log(c_i+s)`，写在 cosine 尺度上是为了
让 alpha=0 原样保留既有分数与同分关系。频次只从训练得到；验证目标用于
衡量指标和选择 alpha，不进入频次计算。原来的评估分桶仍按完整训练历史频次，
不会随着校正强度改变定义。

这个实验问的是：**无需重新学习表示，输出分数的简单调整能修正多少问题？**
它只是有明确成本的假设，不是已证明的去偏方法，也不估计真实曝光倾向。
较大 alpha 可能过度提升从未得到正向监督的候选，导致总体指标下降。
因此同时检查低/中频命中、推荐频次分布及目录覆盖；不能只挑好看的长尾一项。

选择仍使用总体验证 NDCG@10，完全同分保留更小 alpha。若都不如 alpha=0，
就保留原模型、记录负结果。不能事后换选择指标或根据测试分数选 alpha。
这个入口没有测试集开关，不训练或修改原检查点，也不自动把校正选为最终方案。

## 代码与输出约定

`scripts/diagnose_hstu_scores.py` 是独立诊断入口，未修改 `src/`，因此保留旧
检查点严格源码身份检查。配置为 `configs/hstu-score-audit-server.json`，
固定引用此前训练目录 `runs/hstu-microlens/20261022T023420952080Z`。

1. 核对训练报告完成状态、配置、数据哈希、best.pt 哈希、epoch 和模型源码身份。
2. 使用原 Dataset 和原 eval batch=64，得到 `[B,N]` 候选 cosine 分数。
3. `training_counts` 产生两个 `[N+1]` 计数向量，0 为 padding；校正偏移预先
   计算为每档一个 `[N+1]` 向量，每个神经模型 batch 只算一次并复用给 4 档。
4. 使用原 RankingAccumulator：排除 padding 和完整可见历史，同分按 ID 升序。
5. alpha=0 必须复现报告中最佳轮次的全部既有指标、分组和用户数，绝对容差
   1e-12。检查失败就输出 FAIL，不选择新方案。
6. 为每档统计 max(K)=20 的推荐位置数、唯一推荐物品数、目录覆盖比例，以及
   按训练历史频次分组的推荐位置占比。这些是推荐列表分布，不是目标命中率，
   也不能作为线上用户满意度或公平性的证明。

每次写到 `runs/hstu-score-audit/<UTC时间>/results.json`，包含 4 档完整验证
指标与切片、推荐分布、选择结果、配置/训练报告/检查点/数据/脚本哈希、Git、
环境、设备、耗时与显存。执行前后确认数据、训练报告和 best.pt 未变。
神经模型只前向推理；CPU 排名要比较 4 档，不预设这次诊断耗时。
